# Fixes to make, from the 2026-10-06 user-shaped run

Dawn at `cc2d36d` (branch `tl`) was driven like a user in two places: on a Linux box in a tmux
pty against a mock of TAI (`tests/ux/mock_tai.py`), and on the phone "Pong" (Nothing A065,
Android 16, Termux Launcher 1.0.0, live TAI with Gemma 4 E2B and EmbeddingGemma) through adb,
both inside tmux (text captures) and directly in the launcher's terminal (screenshots).
Everything the fork adds worked end to end; the list below is what did not, ordered by how much
it hurts on a phone. "Verified" means seen on screen or in the request log; "inferred" means a
reading of the code or a single observation that was not reproduced.

## Must fix

### 1. A typed task list never becomes a checkbox
Typing `-` at a line start auto-inserts a space (`dawn.c` ~line 378, the `'-' '*' '+'` branch).
The space the writer types next is kept too, so `- [ ] x` lands as `-  [ ] x`, which renders as a
bullet plus a literal `[ ]`. Only pasted or AI-inserted lines get the ☐. Same on upstream
`origin/main`, so inherited, not a fork regression. Verified on host and phone.
Fix: swallow a typed space right after the auto-space, the way the existing `--` case already
undoes it.

### 2. The title job trusts the model's reply verbatim
`dawn_title.c` asks for two to six words, no quotes, no final period, then applies whatever comes
back. A 110-character reply with quotes and a colon became the title (host, mock). On the phone
the E2B title job produced no title within 12 s, so the real-model path is unconfirmed either way.
Fix: validate the reply (2–6 words, strip quotes and a trailing period, reject newlines, prompt
echoes and anything over ~60 bytes) and keep the old title otherwise.

### 3. Image paths resolve against the working directory, not the note
`![…](dawn-table.png)` next to the note rendered as raw text when dawn was started from `$HOME`
and as an image when started from the note's directory (phone, verified by screenshot). Notes
opened from history are never in the working directory.
Fix: resolve relative image paths against `dirname(app.session_path)` before trying the cwd.

### 4. Double-tap on a styled word selects its hidden markup
Double-tapping `**Pong**` selected 3 bytes (the hidden ` **`) and showed "3 sel"; a plain word
("rendering", 9 sel) selected correctly. A following keystroke then replaced the markup and broke
the bold/italic spans (phone, verified by screenshot). The word-byte class in `is_word_byte`
(`dawn.c` ~4275) is applied to raw bytes, so the selection snaps to syntax characters.
Fix: run the double-tap word scan on the rendered run (skip bytes the renderer hides), or clamp
to the inline run's text range.

### 5. Task checkbox tap does not toggle on the phone
With the exact same SGR press/release sequence (`CSI < 0;col;row M` / `m`, confirmed with
`cat -v` on the device), a tap on the ☐ glyph toggles it on the host build (GCC, RelWithDebInfo)
and only places the cursor on the phone build (NDK clang, Release, three tries, direct and via
tmux). `try_toggle_task_box` (`dawn.c` ~4231) returned false on the device; which condition is
unknown. Verified discrepancy, cause inferred.
Next step: a device build with `-O0` or UBSan, or a one-line notice printing `col`, `indent`,
`vrow` and `task_state` when the tap lands on a list item.

### 6. History list overflows at phone width
At 53 columns the history rows wrap: the date column spills onto the next line
("Oct 6, 2026 at 1" / "3:1") and the key hints wrap too (phone, tmux capture). `dawn_render.c`,
history screen.
Fix: drop the time or shorten the date when width < ~70, and let the hint row truncate.

## Should fix

### 7. A small model's "I added it" with nothing added
Asked to append `- [ ] buy milk`, Gemma 4 E2B replied "I have added the task "-  ] buy milk" to
the note." and the note did not change (no tagged block, no tool call). Dawn showed the claim
as-is. Verified on phone.
Fix: when a reply claims an edit (verbs like added/inserted/replaced) but no edit was applied,
append a dim line "Nothing was changed" so the writer is not misled. Also consider showing the
tagged-block syntax to the model with an example in the system prompt.

### 8. Version path in the AI edit confirmation
After an AI edit the chat prints the full absolute path of the saved version: seven wrapped lines
at 44 columns on the host, and on the phone it is `/data/data/com.termux/files/home/.local/share/
dawn/versions/…`. Verified on host.
Fix: "Ctrl+Z undoes it; the previous version is kept" with the path only in the activity list.

### 9. Model picker lists embedding models
The picker shows every entry of `/v1/models` that is not `-vision`/`-audio`, including
`embeddinggemma-300m`, which cannot chat. Verified on host (mock) and in the phone's model list.
Fix: filter on `_capabilities` containing `text_chat` (fall back to all when the field is absent).

### 10. Kitty graphics probe leaks into tmux's window title
Inside tmux the startup APC probe `ESC _ Ga=d,d=a,q=2 ESC \` appears as the tmux window name
(phone, screenshot). Dawn has no `$TMUX`/`TERM=tmux*` guard (`dawn_backend_posix.c` ~414).
Fix: skip the graphics probe when `$TMUX` is set unless `allow-passthrough` is known, or wrap it
in the tmux passthrough envelope.

### 11. "ai ready" on the welcome screen when AI is off
With no `~/.launcherctl/endpoint` the welcome screen still says "✦ ai ready" while the chat
then says "AI is off". Verified on host.
Fix: probe the endpoint file (or the last runtime answer) before painting the welcome line.

## Nice to have

### 12. Cursor parked on an invisible row above the title
Opening a note that starts with YAML frontmatter puts the cursor at offset 0, which draws as a
bar on an empty row above the H1 (phone, screenshot). Fix: start the cursor after the frontmatter.

### 13. Lone caret swallowed as superscript syntax
`^L` in a table cell renders as `L` because `^text^` superscripts hide the caret (host,
verified). Fix: require a closing caret before hiding the opener, or treat `^` followed by a
space or pipe as literal.

### 14. README promises curly quotes
Dashes and ellipses convert; straight quotes stay straight (host, verified; no curly-quote code
in `dawn_md.c`). Fix the README or implement it.

### 15. Typing a fence with a language tag
Typing ```` ```c ```` auto-closes the fence on the third backtick, so `c` lands inside the block as
its first line (host, verified; upstream behaviour inferred, not re-run there). Fix: let the
characters typed on the fence line after the backticks become the info string.

### 16. Model picker tap in the bottom sheet on the phone
Tapping the model name in the sheet header opened the picker on the host (48 and 53 columns) but
not on the phone (three taps, via tmux, same SGR sequence). Possibly the same root cause as #5.
Inferred; retest after #5 is understood.

## Observed and fine
- Footnote auto-stub: typing `[^1]` appends `---` and an empty definition; a hand-written
  definition then duplicates it. Looks intended.
- The 409 `generation_active` path waits with a spinner and resumes; the 400
  `capability_not_supported` path retries without tools and remembers it. Both as designed.
- Dictation marks: the launcher's listen/end marks reached dawn in writing mode (status
  "listening", then back). Phrase insertion needs speech and was only verified on the host by
  injecting marks.

## Not reached

and the meaning index, so the shipped binary has none of them.

### 17. Taps below a heading were one row high in terminals without text sizing (new, fixed)
The block cache counted an H1 as two rows (OSC 66 scale) even when the terminal cannot scale
text, while the renderer drew one row, so every tap below a heading in tmux or a plain xterm
mapped one row too high. `block_set_text_scaling()` now tells the cache whether headers are
scaled, and the header tap mapping follows the same capability. Verified in tmux: tap on the
heading row and on the paragraph below it both land on their own line. On the launcher's
terminal (text sizing on) nothing changes.
